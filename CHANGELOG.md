# Changelog

Versions follow [semver](https://semver.org). Before 1.0, a minor version can change how things work.

## Unreleased

- **`labit --native`: pins from a native app.** A lab with no dev server and no HTML (port 4436 by default) for an app that draws its own window (GPUI, SwiftUI) and posts its pins over HTTP: its pages list is the pages pins were made on (`/app`, `/gallery/inspector`), and `wait` hands the agent the pin's `component`, `written at` and `component used at`, with the GPUI hint for `.rs` sources. The calls are in `docs/native.md`.
- **Status lines lapse, pin numbers are their own.** A pin's status line (`reply --progress`, or the plugin's) counts as a sign of life for 3 minutes, then the pin greys and comes back to the next wait as if it had none; the plugin renews a line only for the session's own tool calls, only on a pin somebody claimed, and says "session activity" (no helper commands). Each new pin takes its number when it is made (the page's highest + 1, even when several are made at once), so two pins on a page never share a number and a resolved pin's number is not given again; older pins keep the numbers they showed.
- **A smaller package (−1.3 KB).** The server bundle drops code nothing reaches: the page-script builder that only a checkout uses is no longer in the npm bundle, the comments API works on the lab's own store directly (no Redis-style command layer), the lab's mark is read from the tab icon file instead of a second copy, and `--help` and a few helpers say the same things in fewer words. Nothing you can use changed.
- Ink on selected words (the `inkOnText` experiment) is gone. Selecting words for a comment gives a pin on them, as it always did; an old `inkOnText` in a settings file gets the "not something being tried now" note and nothing else.
- The server bundle (`dist/local.mjs`) gets the same name shortening the page script has (`scripts/build-cli.mjs`): the npm package is 1.7 KB smaller.
- **Agent pins, six better.** The skill has a short part of its own for them (when to pin, one point per pin, about 8 an ask, read the selector from the file, say how many were left). A browser checks the selector of `labit pin`: the page the pin is on draws it, and when the selector matches nothing it marks the pin, and the command (it waits up to 3 s when a browser has the lab open; `--no-check` skips that) and the agent's next wait say `pin <id> matched nothing on /page: <selector>`; when it matches, the browser saves the element's tag, words, box and heading once, so the pin is found again after edits. With no browser open the pin is saved unchecked, and the command says so.
- **Pins that ask.** `labit pin <selector> "text" --question`, or `--choice "A" --choice "B" --recommend B`, makes the pin itself an asking pin (amber ring); the first message of a thread can now carry choices, and the pick comes back in the next `wait` as `Picked B: …`. The server takes `intent: question` and `choices` on an agent's first message.
- **"Do it" and ticks reach the agent.** A "Do it" button on a pin the agent left sends "Do it" back as a reply marked `doit`; the next `wait` shows it as "<name> said: do it". When people tick (resolve) the agent's own pins, the next `wait` says "ticked: 2 of your 5 pins" once.
- **Pin on words, many at once, on boards.** `--quote "exact words"` makes a text pin on those words (the browser finds them in the element). `labit pin --file points.json` saves a list in one call (ids printed). `--board <name> --frame <id> <selector> "text"` pins on a frame's element, `-` instead of the selector on the frame itself (`--at` px from its top left), and `--board <name> - "text" --at x,y` on the board.
- **Variants behind a dev server.** `labit board new … --of /page --variants N` no longer refuses a page it can't copy (a lab in front of a dev server): each variant is the live page with `?lab-variant=<frame>`, and the agent branches on `new URLSearchParams(location.search).get('lab-variant')` in the page's source. A pick says which branch won and to remove the branching.
- **A board of variants starts with the page as it is now.** `labit board new … --of /page --variants N` adds the live page itself as the first frame, `a`, labelled "now" (the real page, not a copy), and the N copies come after it as `b`, `c`, `d`… so the options sit beside the current version.
- **Arrow keys on a question card.** On a computer ArrowDown / ArrowUp move the ticked row (tried in the page, as pointing does), stopping at the ends, and Enter answers the ticked row. Same rules as Enter and 1 to 6: not while a text box has the focus, no modifiers, the open thread card only; the page does not scroll while they are used.
- **No "sent · undo" strip above the bar.** The first comment of a new pin still closes its card; undo stays for 3 s by opening the pin, and Command-Z. The skill asks agents to put a question's options on the pin they answer (`--choice`), never elsewhere on the page.
- **Section bar: a tap only scrolls, and only new content marks.** Tapping a section in the bar goes to that section and opens no comment; a section is in the half ink only when its own content is new or updated since you last looked, no longer because it holds an unread pin (pins keep their own unread marks). Headings that are titles of repeated items (the cards of a grid, a list, a set of articles) are not sections, so a page of option cards no longer fills the bar with one item per card.
- **The agent's "on it" messages fold and never count as unread.** Once a thread has its answer, the status messages before it become one small muted row, "2 updates ›" (tap to open them in place), in a pin's thread and in the chat. Until the answer comes the latest still shows. They no longer light the pin, the chat count, the section bar or the tab title. The skill now asks agents for no `--on-it` on quick asks, one `--progress` line on long work, `--question` only when blocked, and `resolve` with no words for a plain "go" or a pick. A status that arrives while you type in a thread is added in place, folds in the chat per thread (interleaved threads fold into one row each), and opening a row keeps its place and its keyboard focus. "On it, fixed by…" as a real answer is no longer taken for a status.
- The built page script (`public/_lab/comments.js` and its parts) is no longer kept in git, so two PRs that change the widget no longer clash in it. A lab started from a checkout builds it when it's missing or older than `src/`, `npm test` builds it first, CI builds it before testing, and the npm package ships it built as before.
- **Pins on the same file are named together.** When a wait hands over several pins, a line above them says which share a file (`Same file: options.html: 2, 5, 7`), only for groups of two or more, so one helper can take the group.
- **Helpers, in the skill.** One listener answers every pin itself and hands only long, independent jobs (builds, research) to helpers: one helper per group of pins on the same file, one writer per file, a `--progress` line on each pin a helper works on, and the main agent sends every reply.
- **A progress line is a sign of work, always.** The plugin's hook now renews a helper's line once a minute while the session waits on it, so a long build inside a helper no longer ends in "Still waiting for your answer … no sign for 3 min" while it runs. The hand-off's reminder and the 2-minute "not answered" check both count a line from the agent or the hook (tests added).
- The ¼ speed key can be moved like the others: `slow` in `shortcuts` (`labit.json` or your settings) was refused as "not an action" and S stayed. Another action put on S is now said when the lab starts, as for any key used twice.
- Select mode is gone (it was the flag `select`, **V**, and select in the ⋯ menu): the code, its styles and its key with it. The quick actions on pins, words and areas stay. An old `select` under `flags` in `labit.json` or your settings is now said at start as "not something being tried now" and otherwise ignored, and a `select` under `shortcuts` as "not an action".
- **Undo a tap on a question.** A tap shows "Picked B · undo" for 5 s; the pick goes after that, or at once when the card closes. Undo puts the rows back.
- **Questions in the chat.** The agent's question with choices shows its rows in the page chat too, and picks work the same.
- **A question card no longer focuses its reply box on a computer**, so keys 1 to 6 pick right away.
- **Keys 1 to 6** pick that choice of an open question on a computer (A is 1), with the same undo; ignored while a text box has the focus.
- **A scroll is not an answer.** On a touch screen a press that moved more than 8 px picks nothing.
- **A line under each choice.** `labit reply --choice "Tabs" --hint "less scrolling" --choice "List"`: the hint (up to 120 characters, stored as `hints`) shows muted under its row. An older page ignores it.
- **The question card stays in the window** on a computer: 8 px from the left edge, never past the bottom.
- The labit skill says when to ask with `--choice`: copy, names, a risky step; one line per choice, always `--recommend`, one open question per pin; and to use a board, not choices, when the options are looks (layout, colour, spacing).
- **A tap answers a question.** A question's choices send on tap, no Keep; pointing at one on a computer still tries it in the sentence. The rows are as wide as the messages.
- **Drawings are quick actions.** The agent gets an `action:` line from the mark: X, strike or scribble remove; circle, box or a wavy line fix; underline rewrites; a side line reworks the block; an arrow moves (beside what's there); a caret adds. Words in the thread win.
- **A drawing sends with Enter, no words needed.** Its box opens with the lines; Enter sends it as what it reads as ("circled"), or type a few words first.
- **The agent is told where to look.** On a plain HTML page each comment gets `in file: page.html:30`, and an arrow's ends name their card or section. In sims this cut a third of Haiku's time in the model.
- **Drawn lines are a red pen**, as wide as you pressed (a pen's pressure, or slower = wider), and settle to 35% once sent, full on hover or open. Arrows get a clean head at the tip, whatever the hand drew.
- **A drawing with several marks lists each one** with what it is on, in the order drawn ("mark 1: arrow from Integrations to Weekly digest", "mark 2: circled on Alerts"), so the words can refer to them.
- **Hold Shift while drawing** and a line drawn about straight comes out straight, flat, upright or at 45°; a rough box comes out a clean rectangle and a loop a clean ellipse.
- **Lines are smooth curves** through the kept points, so thinned lines stop looking jagged. The line you tap to open a drawing is 28 px wide, about a fingertip.
- **A tapped action closes at once** (go, fix, remove…): no undo card to close by hand on a phone. Command-Z still takes it back on a computer.
- **Drawing edge cases fixed:** loops that stop short or run past their start, wavy and slightly crooked lines, a palm on the glass, a scroll mid-stroke, a stroke into a frame or off the window, D typed into the box, a cancelled stroke, a loop ending on its own start, long scribbles and ten-stroke drawings kept whole, drawing over links, buttons and earlier lines.
- One board. `/_lab/board/<name>` is now the same board view a page's board link opens, over an empty page: a bar with the board's name, and "‹ back" when the address names its page (`?of=`). ⇧B, Esc on an empty board and the browser's back go there as before, and the camera stays in the address. The package ships one board file (`boardview.js`), not two.
- Fluid goes. Shift-selecting words on a computer opens the ordinary comment card on them (pinned at the words, with your actions row), not the dialog that followed the words; on a phone, selecting words no longer brings up the comment · rewrite · cut bar (hold to comment as before). `fluid.ts`, its styles, `test/browser/fluid.mjs` and the `fluid` CI job go.

## 0.7.0 · 2026-11-19

The first release under a new license, and a big one: boards, select mode, drawn pins, one list of actions, undo, and labs that wake your agent and follow their install. MCP and cloud labs are parked. The full list of changes as they landed is at the end.

### Before you update

- **License.** labit 0.7.0 and later are under [PolyForm Small Business 1.0.0](LICENSE), not MIT: free for people and companies with fewer than 100 people and under $1M in yearly revenue, a paid license for larger ones. 0.6.2 and earlier stay MIT.
- **MCP is parked** (kept whole on the `park/mcp` branch). `labit mcp` is gone; agents use the command line: `wait`, `reply`, `resolve`, `pin`. Drop any `claude mcp add labit …` line and use the plugin or `labit skill`.
- **Cloud labs are parked** (on `park/cloud-lab`). `labit add` / `labit remove`, saved cloud pages, invite links for hosted labs and the Vercel deploy are gone; labit is the local lab only.
- **Actions are a new setting.** `actions` in your own settings.json is an ordered list of `{ "name", "prompt" }`, seeded once from your old buttons. The old `{ words, spot }` form and a project's `actions` are no longer read.
- **Keys moved.** `1` toggles comment / pointer, `C` is comment mode, `T` opens the chat (was C), `V` is select mode, `D` held draws, `P` pauses and `S` slows motion. Go mode (`2`), `3`, zoom and the `a` key are gone; a stale key in settings is ignored with a note.
- **Zoom is out** for now: no zoom pins, `labit zoom` or zoom skill. Old zoom pins show as ordinary comments.
- **`.lab/` is tidier.** Seven small state files become one `state.json`, moved on the first start. A lab last run before 16 Nov must run `npx @leonidstern/labit@0.6.2` there once first.
- **npm gets releases only.** Merges to main no longer publish `next`.

### New

- **Boards.** `labit board new "<topic>" --of /page --variants 3` copies a page into variants side by side; `--widths` and `--flow` show real pages at several sizes or in order. `/_lab/board/<name>` is one canvas of live frames to pan, zoom, select and enter, with pins on frames or on the board. Frames can be resized, duplicated, archived and undone; `labit board pick` marks the winner and hands the agent what to put back into the real page. A board a page links opens over that page; Space + drag pans, zoom stays steady and the edges just stop. Boards are in ⌘K.
- **Select mode** (flag `select`). `V` picks a block; the same action box as a pin opens on it, one tap one pin.
- **Drawing pins.** Hold `D` and drag: circles, arrows, crossings-out and carets reach the agent as what they read as, plus the path.
- **One list of actions** for pins and select: a line of chips that fits the box, **…** for the rest, each sending `<name>: <your words>` with its full prompt to the agent. Hold or right-click a row to edit it in place; delete (with undo) and + add are there too.
- **Undo a pin.** For 3 s after you send, its card shows **undo**; a press on the page lets the card go without starting a new pin.
- **Choices.** `labit reply --choice A --choice B [--recommend B]` asks with options; each is tried live in the sentence, and Keep sends the pick back as `Picked B: …`.
- **Never stuck.** `reply --progress "…"` keeps a live status line on the thread; the pin's ring shows sent, picked up, working, waiting in line, quiet, or asking; the pill counts the queue. A hand-off nobody answers within 2 minutes goes to the next wait.
- **Claude Code wakes for pins.** The plugin's hook gives the session that listened last a new turn when pins land while it isn't waiting, even while it is busy, and from any folder.
- **Labs & pages (⌘K).** One list of every page in every running lab, last active first, with who listens; archive a page or a whole lab, name a lab (`labit --name`), hop between labs from a phone without a new invite.
- **Labs follow their install** and come back on the newest build once nobody is working; an idle lab parks itself after an hour (`LABIT_IDLE_MS`). `labit list` and the ⋯ menu say which build each lab runs.
- **Updates from the page.** For a lab run from npm, the ⋯ menu offers a newer release; pressing it asks your agent, and `labit update` prints what changed and moves the lab onto it. A held reload shows as a small green "!" on the labit mark.
- **Section bar** on lab pages (any other page can ask with `<meta name="lab-sections" content="on">`): every section along the top, new and updated ones and unread pins in the page's half ink, kept read per person across devices. It floats over pages with their own top bar, hides while a board is open, and never prints.
- **Motion control.** Hold ⌥ over a video or loop for pause, ¼ speed and its moment in ms; on phones it sits in the thing's corner. Every pin on a loop, video or GIF keeps its moment for the agent, and a chip on the pin pauses the page there again.
- **Agent pins.** `labit pin <selector> "text"` leaves the agent's own numbered pin, wearing labit's mark.
- **Action buttons on a page.** `data-lab-action="merge #224"` makes an element open a ready comment the agent acts on; `data-lab-confirm` asks first.
- **`labit publish`** puts a one-off page into your pages lab and prints its link; **`labit skill`** prints the agent's instructions for agents without the plugin.
- **Experiments** in the ⋯ menu switch flags on and off from the page, saved to your settings.
- **Trying, off by default:** `native` lets the browser place pins, cards and menus (CSS anchor positioning, popovers, the Navigation API) in Chromium and Safari 26; `inkOnText` shows a comment on words as low ink under them instead of a pin.

### Better

- Threads arrive whole: a reply comes with the opening comment and its messages, the new ones marked, so an agent no longer answers one thread with another's context.
- Listening is per page: a page no wait covers says so, two sessions on one lab no longer end each other's wait in silence, and a `wait` outlives a lab restart.
- Pins: done pins full size and faded, pins whose spot is gone leave the page (the ⋯ menu lists them to drag back), quoting snaps to whole words, pins move less and keep their state across redraws.
- Phones: chat and threads keep the newest message above the keyboard, pinch zoom keeps the widget usable, a hold always focuses its box, wifi guests stay in while they use the lab.
- Smaller to install: one minified CLI and no changelog in the npm package.
- One motion system (tokens in `docs/motion.md`) and one design census checked in CI.

### Fixed and safer

- A symbolic link into `.lab` or at a dot file is no longer served (it exposed the lab's keys).
- Behind `--proxy` another site can't write to your dev server through the lab; only this computer keeps rules; request bodies are capped at 256 KB.
- A comment whose save failed is kept and retried, not lost; a broken `settings.json` or `replies.md` is no longer written over.
- On Linux every change to a board file or a page saved by a rename reaches open pages, not only the first.
- With ⌥ held, motion controls no longer run off to the far corner of a box when the pointer crosses a gap.
- `labit publish` can no longer delete its own source; localhost links reach the agent as written; IME Enter in Safari no longer sends half a word; a crashed lab no longer misroutes `wait` and `pin`.
